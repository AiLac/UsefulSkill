# Codex 角色故障排查

先确认正在检查的文件是独立角色还是 `config_file` 引用的配置层，再使用正确模式。
本文基于 2026-11-13 的 `rust-v0.167.2` 源码核对；具体诊断文字及命令以目标版本为准。

```bash
python "<技能目录>/scripts/validate-agent.py" "<独立角色文件或目录>" --strict
python "<技能目录>/scripts/validate-agent.py" "<配置层文件>" --kind role-layer --strict
```

## 先处理静态检查结果

| 现象 | 可以确认什么 | 下一步 |
| --- | --- | --- |
| TOML 无法解析 | 文件语法无效 | 按诊断位置检查引号、括号和表头；`name` 用赋值语法 |
| 独立文件缺必需项 | 未提供非空 `name`、`description` 或 `developer_instructions` | 补齐字段；若实际是注册配置层则使用 `--kind role-layer` |
| 已知字段类型错误 | 该值与本脚本覆盖的结构不符 | 先改类型，再核对取值；字符串 `"false"` 不等于布尔值 `false` |
| 文件不是 UTF-8 | 无法按技能要求读取文本 | 将配置保存为 UTF-8，再检查 |
| 不同文件的角色名称冲突 | 扫描输入中存在重复身份 | 检查是否误建角色；有意做作用域覆盖时核对目标版本的加载规则 |
| 字段会被角色应用阶段忽略 | 写入该字段不能证明它改变了角色行为 | 放到正确的父配置位置，或移除不需要的覆盖 |
| `WARNING` 提示未知字段 | 校验器未覆盖该字段 | 查目标版本规范或内部读取实现；不要直接断言它有效或无效 |
| 无 `ERROR` 但严格模式失败 | 存在尚未处理的警告 | 逐条处理，不通过去掉 `--strict` 伪装为全部通过 |

文件名与 `name` 不同、中文指令较短，本身不属于失败条件。
`[capabilities]`、`[constraints]` 及其业务预算字段没有本基准的原生角色依据；
若是内部扩展，应给出实际实现来源，而不只依赖生成它们的 Agent 的解释。

## 文件通过检查，但角色没有加载

1. 核对目标 CLI 版本、实际个人配置目录和项目工作目录。
2. 确认独立文件位于该版本会发现的位置；项目配置是否被加载还受项目信任和管理策略影响。
3. 对显式注册，检查父 `config.toml` 的角色表以及 `config_file` 相对路径。
4. 在目标客户端重新加载配置并检查诊断。若帮助中提供 `codex doctor`，可以使用它；
   其他版本使用其实际提供的诊断方式，不猜测命令。
5. 无法运行目标客户端时，将加载状态标为未验证。

静态校验器不读取完整父配置，也不会替用户建立信任配置、绕过管理策略或安装模型。
目标版本可能跳过无效角色并继续运行；不能因为主会话成功启动，就认为指定角色已经加载。

## 角色已加载，但没有被使用

明确要求按 `name` 委派一个小任务，并观察实际创建的子 Agent 线程。
检查是否创建了其他角色、是否存在并发限制，以及项目指令是否要求不同的处理方式。
仅写一段 `description` 不足以证明发生了委派；也不要把模型自述“我已使用角色”作为唯一证据。

## 模型或输出行为与预期不同

| 现象 | 排查顺序 |
| --- | --- |
| 实际模型与文件不同 | 确认目标角色已加载且确实被调用，再核对角色、委派请求、全局默认和父会话设置 |
| 内部模型 ID 被拒绝 | 以内部模型目录和运行错误为依据；不要自动换成公开模型 |
| 推理强度不被接受 | 核对模型支持的值；只改模型可能仍沿用此前解析的推理强度 |
| 子 Agent 缺少材料 | 检查实际委派消息和上下文继承方式，补充任务必要输入 |
| 结论格式不稳定 | 在 `developer_instructions` 中明确返回内容，并用真实任务验证 |
| 调用次数或分析轮次超出要求 | 检查是否存在实际执行器计数；仅写提示词不能提供硬限制 |

角色指令是 developer 指令内容，不能替代上级指令和宿主权限控制。

## 权限和 MCP 与预期不同

| 现象 | 原因或核对点 | 处理方式 |
| --- | --- | --- |
| 角色写了 `sandbox_mode = "read-only"` 仍能写文件 | 角色字段不替换父会话沙箱 | 检查父会话及工具实际权限；需要时按授权调整父配置 |
| 关闭 shell 后仍能调用外部工具 | shell 与 MCP 等是不同工具通道 | 分别核对父会话中的服务器、工具和权限设置 |
| 角色中配置的 MCP 没出现 | 角色文件不是父会话 MCP 配置入口 | 在父会话确认服务器已配置且可用 |
| `features.<名称> = true` 没有启用功能 | 角色只应用有限的关闭项 | 核对父会话提供的功能，不通过角色字段扩权 |
| `skills.config` 没有匹配技能 | 选择器与真实技能不符，或同时填写了 `name` 和 `path` | 使用一个正确选择器，并检查实际技能状态 |
| `skills.max_context_tokens` 没有限制总上下文 | 该字段描述技能目录预算，角色应用也不保留它 | 明确真实预算需求，由相应执行器处理 |

## 报告结果

提供目标版本、文件路径、配置形式、执行过的命令、退出码及关键诊断。
分别说明静态检查、配置加载和实际委派是否完成；缺少内部运行证据时，明确列出未验证项。
字段依据见 [配置参考](config-reference.md)，可复制模板见 [示例](agent-examples.md)。
